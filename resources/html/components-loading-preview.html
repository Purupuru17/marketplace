4. Top Progress Bar (navigasi halaman / route change)

Muncul fixed di paling atas layar, tanpa mengganggu konten — dipakai saat pindah halaman/fetch data awal, bukan untuk submit form.

5. Full-Screen Overlay (aksi kritikal, mis. submit Checkout)

Membuat pesananmu...

Blocking, mencegah double-submit. Dipakai HANYA untuk aksi yang tidak boleh diulang tanpa sengaja: Checkout, Batalkan Pesanan, Hapus Akun.

6. Skeleton (loading konten, bukan aksi)

Dipakai saat fetch list/grid pertama kali. Beda tujuan dari spinner: skeleton untuk "menunggu data", spinner untuk "menunggu hasil aksi".

7. Toast (sudah ada) — 3 varian status

Produk berhasil ditambahkan ke keranjang
Gagal memperbarui alamat. Coba lagi.
Koneksi lambat, memuat ulang...

8. Inline Field Error — saran tambahan

Format email tidak valid

Toast cocok untuk hasil aksi (submit sukses/gagal secara keseluruhan). Untuk kesalahan validasi per-field saat mengisi form, inline error di bawah field lebih membantu — user langsung tahu field mana yang salah tanpa toast menutupi konten.

9. Persistent Banner — saran tambahan

Kamu sedang offline. Beberapa data mungkin tidak terbaru.

Untuk kondisi yang berlangsung lama (bukan sesaat seperti toast) — mis. mode offline, akun belum diverifikasi, toko sedang tutup. Menempel di atas konten sampai kondisinya berubah, tidak auto-hilang seperti toast.
